# 09 · 前端设计（笔记站 + 管理台）

> 2026-09-25。用户要求：先想清楚各板块与整体功能结构，并找"实用但不泛滥"的功能，再动手。
> 依据：docs/05（学习科学调研）、业界文档站设计手册（度量/行距/目录位置/阅读时长的具体数字）、
> 以及本仓库现有的产物形态（笔记结构、META 元数据、账本状态、余额接口）。

## 0. 原则（先定约束，再谈功能）

1. **阅读优先**：笔记站是"读"的产品。排版本身即界面——度量、行距、层级比装饰重要。
2. **零依赖、零构建**：站点是原生 Node + 手写渲染器，1.2G 内存的机器上跑得很轻。为界面引入
   构建链与框架会把这个优点赔进去。交互用几十行原生 JS 就够。
3. **功能准入线**：每个功能必须能回答"**它替读者减少了哪一次操作或哪一次困惑**"。
   答不上来就不做——这是"不泛滥"的判据。
4. **内容站不做动画**：设计手册明确写着"读者觉得动效烦人，不是愉悦"。只保留必要的状态过渡。
5. **默认浅色**：研究结论是浅色在正常视力、小字号下阅读表现更好；深色做成可选开关。
6. **管理台分区，不散按钮**：现在管理页是一堆按钮堆在一起，要按"一件事一个区"重排。

## 1. 信息架构

\`\`\`
course.law-tech.dev
├── /                        首页：一句话说明 + 搜索 + 课程卡片
├── /courses/<课程>/          课程页：该课程全部课次 + 课程级汇总
├── /notes/<课程>/<课次>.html  单课笔记（核心页面）
├── /concepts/               概念索引（跨课次）★
├── /statutes/               法条索引（按条号反查课次）★
├── /cases/                  案例索引 ★
├── /search?q=               站内搜索
└── /admin                   管理台（令牌保护，未配令牌一律拒绝）
\`\`\`

★ 这三页是调研里点名的"治割裂"主力（跨节概念线），也是法学复习时真正会去查的东西：
**"这个概念老师在哪几讲讲过、每次讲法有什么不同"**、**"这个条号在哪几处出现过"**。

## 2. 单课笔记页（核心）

### 2.1 布局

\`\`\`
┌ 阅读进度条（3px，顶部，不抢视线）
├──────────────┬───────────────────────────┐
│ 左栏目录      │ 正文（度量 38em ≈ 38 汉字/行）│
│ sticky       │  简报卡片                   │
│ 全部 h2/h3   │  本课在课程中的位置          │
│ 当前节高亮    │  知识地图（Mermaid）         │
│              │  体系线索 → 核心问题 → 学习目标│
│ 预计阅读时间  │  分节正文（节末自测·答案折叠） │
│ 字号调节      │  复习层（索引表/易错点）      │
│              │  附录（事务与发散、时间轴对照）│
│              │  知识连接 / 元数据（折叠）    │
└──────────────┴───────────────────────────┘
                                    [回到顶部]
\`\`\`

- 目录**放左栏**（右栏会被当成广告跳过），含**全部**小节，**文字与标题完全一致**，
  用 IntersectionObserver 高亮当前节（不是滚动位置算术）。
- 只有"独立成栏"的目录才 sticky；正文内的目录不 sticky（避免与页面其它粘性元素打架）。
- 移动端：目录折叠成显式的「本页目录 ▾」，**不藏在无名图标后面**。

### 2.2 功能清单

**必备（阶段 1）**

| 功能 | 为什么 | 成本 |
|---|---|---|
| 左栏目录 + 滚动高亮 | 长笔记（1.4 万字）没有目录等于每次重读 | 中 |
| 阅读进度条（2–4px） | 知道"还剩多少"，是长文的实际决策依据 | 低 |
| 回到顶部 | 长页从底回顶要滑很久 | 低 |
| 预计阅读时间 | 帮读者决定"现在读还是收藏"（中文按约 400 字/分钟） | 低 |
| 上一讲 / 下一讲 | 复习常按课次连着看 | 低 |
| 标题锚点可复制 | 同学之间分享"某一段"很常见 | 低 |
| 打印样式 | 法学复习大量依赖打印；隐藏目录/进度条、正文放宽 | 低 |

**实用加分（阶段 4，逐条都要过准入线）**

| 功能 | 替读者省掉什么 | 数据来源 |
|---|---|---|
| ~~自测打勾 + 错题清单~~ | — | **用户否决（2026-09-25）：复习用不上** |
| **阅读位置记忆** | 长文分几次读，不用每次找"上次到哪" | localStorage，按 slug |
| 字号调节 A- / A+ | 长时间阅读的字号偏好因人而异 | CSS 变量 + localStorage |
| 深色模式开关 | 夜间阅读（默认仍是浅色） | CSS 变量 |
| 概念悬浮卡 | 读到一个概念时不用跳走：给一句话定义 + 它在哪几课出现过 | 概念索引（META） |
| 法条反查 | 正文里的《X法》第 N 条可点，跳到法条索引 | 法条索引（META） |
| RSS / 更新提醒 | 有新笔记时不用自己来刷 | 静态 feed.xml |
| 键盘快捷键（\`/\` 搜索、\`j/k\` 上下节、\`t\` 回目录） | 键盘用户少一次鼠标寻找 | 原生 JS |

**明确不做**

| 不做 | 为什么 |
|---|---|
| 滚动动画、视差、渐变特效 | 手册明确：内容站动效让人烦 |
| 评论、点赞、账号体系 | 个人站没有社交需求；多一套身份系统就多一份维护 |
| 在线批注/协作 | 用法不明，成本高 |
| 花哨的 3D 知识图谱 | 好看，但复习时不会用；一张 Mermaid 图足够 |
| 站内 AI 问答 | 现在最该做的是把笔记本身做扎实；问答会诱导跳过阅读 |

## 3. 首页与课程页

- **首页**：一句话说明这是什么 + 搜索框 + 课程卡片（课程名、课次数、最近更新）。
  不要做营销式大标题；这是给自己和同学用的工具。
- **课程页**：该课程课次列表（新在前）+ **课程级汇总**：这门课出现过的概念、法条、案例
  （来自各课次 META 聚合）。复习一门课时的入口就在这里。

## 4. 索引页（阶段 2，价值最高的一块）

| 页面 | 内容 | 依据 |
|---|---|---|
| 概念索引 | 概念 → 出现在哪些课次；每个课次一行写"讲法差异/递进" | 调研 §M3「跨节概念线」是治割裂主力 |
| 法条索引 | 按《法律名》分组、条号排序 → 哪几课讲过、老师给的适用条件 | 调研 §M6 |
| 案例索引 | 案例 → 争点 / 结论与规则适用 / 老师评价 / 出处课次 | 调研 §M7 |
| ASR 更正表 | 转写听错的词 → 应为 → 依据（全站汇总） | 调研 §M10；这块只有我们这种"语音转写→笔记"的链路才有 |

**这需要后端配合**：`publish` 目前只输出标题与摘要；要把 META（概念/法条/案例）与
ASR 更正表抽成结构化数据写进站点索引（`index.json`），索引页与搜索都吃它。

## 5. 搜索

- **纯客户端**：索引 JSON 里含 课次标题、摘要、小节标题、概念、法条、案例；
  搜索在浏览器里做，不引入服务端与分词库。
- **中文处理**：用字符二元组（bigram）匹配 + 权重（标题/概念 > 摘要 > 正文），
  避免引入分词依赖；命中处高亮，结果里显示"课程 · 课次 · 出现在哪一节"。
- 键盘：\`/\` 或 \`⌘K\` 聚焦，\`Esc\` 关闭，方向键选择。

## 6. 管理台（四个区，按"一件事一个区"收束）

第一版设计列了八个区，用户反馈"区块太多"——八个区等于没有区。收束成四个，
每个区内部再分组；**判断标准是：一个区对应一类操作，而不是一类数据**。

| 区 | 区里有什么 | 需要的后端 |
|---|---|---|
| **概览** | 需要处理的事（等你上传课件的课次 / 卡住的课次 / 发送失败的通知）+ 状态卡（阶段分布、余额、磁盘）+ 最近一次运行 | 补余额与"待办"聚合 |
| **课程** | 课次表（课程/课次/阶段/尝试/错误）+ 每行操作（重跑、重置）+ **展开即该课次的材料**（上传、已有课件、`_unassigned` 归类） | 补 retry / 材料列表 / 归类 API |
| **笔记** | 逐模块预览 + 只重写某模块 + 重新拼装 + **重发通知** + 体检结果（note-lint） | 补模块列表 / revise / 通知重发 API |
| **设置** | 运行（手动触发、运行历史，已有）+ 配置（模型与角色、成本窗口、篇幅预算、写作单元数、并发、保留策略，表单化落盘） | 补配置读写 API |

**把"材料"并进"课程"、把"通知"并进"笔记"、把"运行"并进"设置"、把"成本"并进"概览"**——
因为它们分别是同一件事的不同侧面：给课次传课件、让笔记重新生成并推出去、调完参数看运行结果。

## 6.1 视觉方向（用户反馈：太复古，像 Win98）

现状问题：管理页是"灰面板 + 原生按钮 + 大片 monospace"的十多年前后台样式；
笔记站是暖白纸感，虽然适合阅读，但**外壳（导航、元信息、按钮）也用了衬线**，整体偏旧。

改法：**正文与外壳分开**——

| 部分 | 字体 | 理由 |
|---|---|---|
| 阅读正文 | 衬线（宋体 / Noto Serif CJK） | 长文阅读的既定选择，保留 |
| 其余一切（导航、元信息、目录、按钮、表单、管理台） | 现代无衬线（system-ui / PingFang SC / Segoe UI） | 界面元素用无衬线是现代网页的默认，也是"不显旧"的关键 |

配色改为中性现代：白底、冷灰层次（#e7e9ec 分隔线、#7a828a 次要文字）、
单一强调色（沿用墨绿 #2f6f61 作为身份色）、圆角 12—16px、极轻阴影（不叠重投影）。
状态用**色点 + 文字**的 pill，而不是彩色大色块。按钮分三级：主按钮（实心）、次按钮（描边）、
文字按钮。表单有 focus ring。所有交互有 hover / focus-visible 状态，但**不加动画**（内容站）。

UI 组件统一走一套 CSS 变量（`--bg / --ink / --line / --accent / --radius / --shadow`），
为以后的深色模式留好接口。

## 7. 实施顺序

| 阶段 | 范围 | 验收 |
|---|---|---|
| **1** | 笔记页阅读体验（目录/高亮/进度/回顶/时长/上下讲/锚点/打印）+ 首页 + 搜索 | 手机与桌面各读一篇；目录高亮正确；打印预览无目录与进度条；键盘可达；首屏不加载第三方脚本 |
| **2** | 结构化索引（publish 产出）+ 概念/法条/案例/ASR 页码 | 概念页能反查课次；法条页按条号排序；三个中文关键词搜索都命中正确课次 |
| **3** | 管理台分区重构（概览/任务/材料/笔记/通知/运行/配置/成本） | 不打开终端就能完成"传课件 → 只重写某模块 → 重发通知" |
| **4** | 加分项：阅读位置记忆、字号调节、深色模式、RSS、概念悬浮卡、法条反查 | 每项都能在真实复习中说出"省掉了哪一步" |

已由用户拍板：**索引页（阶段 2）要做**；**不做打印优先**（复习不靠打印，只留一份最小打印样式兜底）；
**不做自测打勾与错题清单**。

## 8. 待用户确认的三个取舍

1. **索引页要不要做**（阶段 2）：价值最高，但要改 `publish` 输出结构化数据（约半天）。
2. **自测打勾与错题清单**：这是把"检索练习"落到实处的唯一交互，但需要本地状态。
3. **是否要打印优先**：如果复习主要靠打印，排版可以按 A4 优化（分页、页眉页脚）。
