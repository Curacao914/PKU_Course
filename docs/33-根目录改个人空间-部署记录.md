## 四、本轮发现（不阻断，已记录）

1. **Cloudflare 会把 `/` 的登录态响应缓存**：origin 返回的是 `cache-control: private, no-store`（本机直连 3101 实测），但经 Cloudflare 后变成 `private, max-age=300` 且 `cf-cache-status: HIT / age: 23`——说明该 zone 上有缓存规则覆盖了源站缓存头（早期为公开站点配的 Cache Everything 一类）。
   当前**无数据风险**：该 HTML 是与账号无关的静态壳（OWNER/MEMBER 两份逐字节相同、不含任何账号数据），匿名请求也仍是 302 且 cf=BYPASS。
   但建议加一条 Cloudflare 规则：对 `course.law-tech.dev/` **Bypass cache**（或开启"尊重源站缓存头"），否则将来一旦把账号信息渲染进 HTML 就会跨账号命中缓存。
2. **发布顺序**：本次 release 重启服务后、nginx 更新前的 `40 秒里，`/` 会落在公开进程 → 302 回 `/` → 又回到公开进程，**形成短暂重定向环**（已随 nginx reload 消失，实测确认无环）。以后这套"根路径换宿主"的改动，建议 nginx 先改或与 release 同批执行。
