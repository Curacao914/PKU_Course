# 微信推送故障诊断

日期：2026-09-25
状态：**根因已定位，修复需人工介入**。

## 结论（一句话）

`openclaw message send` 报成功但消息不达，是因为 **CLI 连不上网关，于是回退到本地处理**；
本地实例的 contextToken 存储是空的，微信侧就把消息丢了。而 CLI 连不上网关的原因是
**设备身份变更后需要重新批准，而批准本身又要求先能连上网关**——一个闭环死锁。

## 证据链

| 观察 | 说明 |
|---|---|
| 发送返回 `handledBy: core` | 消息由 CLI 本地处理，不是网关 |
| 修复前网关日志**完全没有**发送痕迹 | 说明从未进入网关的消息流程 |
| 补上 agent 的 message 工具并重启网关后，插件日志出现 `sendWeixinOutbound` / `sendMessageWeixin` | 说明消息终于推进到了通道层 |
| 但每次都带 `contextToken missing for to=…, sending without context` | 微信机器人 API 需要按 (账号,用户) 的会话令牌，缺失时微信侧丢弃 |
| 账号级凭证存在：`debug-check: hasContextToken=true` | 该值来自**入站**消息自带，不是查表得到的 |
| 磁盘上的凭证键与发送地址**逐字节一致**（SHA256 相同，38 位） | 排除键不匹配 |
| 网关启动日志 `restoreContextTokens: restored 1 tokens` | 凭证活在**网关进程**里，CLI 回退到本地时没有它 |
| `gateway closed (1008): pairing required: device identity changed and must be re-approved` | 死锁的直接证据 |

## 死锁细节

```
CLI 想连网关  →  网关：设备身份变了，需重新批准
CLI 想批准    →  批准需要通过网关连接
CLI 带 --token →  仍然被 1008 拒绝（token 认证不绕过设备批准）
```

`openclaw devices list` 走的是本地回退，所以会显示"设备已配对"——这是**本地视图**，
与网关侧要求的重新批准并不矛盾，容易误判。

## 已做的修复（有效但不充分）

1. **给 agent main 补上 message 工具**
   ```json5
   { agents: { list: [ { id: "main", tools: { alsoAllow: ["message"] } } ] } }
   ```
   用 `alsoAllow`（增量白名单）而非 `allow`，避免覆盖既有策略。
   配置已备份为 `openclaw.json.course-bak-<时间戳>`。
   效果：消息从"完全没进网关"变成"进到通道层"。

2. 重启网关使配置生效（网关 readyz 200，五个服务全部 active）。

## 待人工处理

### 方案 A：通过 Control UI 批准设备（推荐，最小改动）

```bash
ssh -L 18789:127.0.0.1:18789 -i ~/.ssh/lawtech-tencent ubuntu@124.222.111.108
# 然后浏览器打开 http://127.0.0.1:18789/ ，在设备页面批准待处理请求
```

Control UI 用 `gateway.auth.mode=token`，令牌在 `openclaw.json` 的 `gateway.auth.token`。
批准后 CLI 即可连上网关，发送会走网关（带着凭证），投递应当恢复正常。

> 注意：Control UI 当前 `allowInsecureAuth=true`，若要经隧道公开暴露需先评估。

### 方案 B：让发送在网关内部完成（最稳，工作量更大）

写一个 OpenClaw 插件（类似既有的 law-tech-wechat-relay）在网关进程内消费本机账本并投递。
好处是**彻底不依赖 CLI 的设备授权**，而凭证本来就在网关进程里。
代价是要维护一个 OpenClaw 插件，并在网关侧部署。

### 方案 C：恢复 cli.law-tech.dev 的用途

实测 `cli.law-tech.dev → :3001` 与 `mypilot.law-tech.dev → :16321` **两个后端都没有服务在跑**
（返回 000）。若 `:3001` 原本就是网关/控制台入口，可把 ingress 改指 `127.0.0.1:18789`
恢复访问；但这会把控制台暴露到公网，需先关掉 `allowInsecureAuth`。
