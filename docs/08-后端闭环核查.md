# 08 · 后端闭环核查（2026-09-25）

> 用户问："后端和数据库这一块，还有什么没有闭环的吗？"
> 本文逐阶段核查，标准是三条：**能跑通**、**失败有明确去向**、**人工能恢复**。
> 缺任何一条都算没闭环。核查当天的两处"静默失败"已当场修掉。

## 一、逐阶段核查

| 阶段 | 成功条件 | 失败去向 | 人工恢复 | 结论 |
|---|---|---|---|---|
| discover | 新回放登记进账本 | 记录错误，回显在运行摘要 | 再跑一次 | ✅ 附：发现新课发一条短通知 |

## 二、数据库

账本（`~/.course-worker/ledger.sqlite`，node:sqlite）承担：任务阶段、租约、尝试次数、
事件流、投递队列。核查结论：

| 项 | 状态 |
|---|---|
| 阶段与终态 | ✅ 完整；`needs_attention` 原先从不产生，现在会 |
| 幂等 | ✅ `replay_key` / `dedupe_key` 唯一约束；重复发现不重复登记 |
| 租约 | ✅ 带自续期；进程被杀后租约到期可重新领取 |
| 事件流 | ✅ `task_events` 记录每次阶段变更与人工重置 |
| 投递队列 | ✅ pending → claimed → sent/failed；可重发 |
| **备份** | ⚠️ **没有**。账本与课次状态是流水线的记忆，丢了要重跑（钱能补，时间补不回来） |
| **清理** | ⚠️ 没有 `prune` 命令。今天手工清了 3.5G→1.4G（已转录课次的媒体与分片再生得出来） |

## 三、原先没闭环的三件事（2026-09-25 全部做完）

| # | 事项 | 现状 |
|---|---|---|
| 1 | 课件上传入口 | ✅ 管理台可直接上传：`PUT /api/admin/materials`，归属用界面上的课程/课次/作用域选择器给出，**文件名不需要任何约定**（实测传"老师发的课件（第4讲）.pptx"正常归档解析）。收件箱那条路也放宽了：文件名对得上账本里的课程与课次就自动归档，认不出来才停到 `_unassigned` |
| 2 | 清理 | ✅ `course prune`（默认预演，`--apply` 才删）。策略见下 |
| 3 | 账本备份 | ✅ `course backup`：SQLite `VACUUM INTO` 一致性快照（库在被写也能安全复制），账本与站点发布库各留最近 7 份 |

配套定时器 `course-maintenance.timer`：每天 **03:40** 先备份再清理（避开两次检测与谷价写作窗口）。

### 3.1 保留策略（用户明确要求）

| 类别 | 处理 |
|---|---|
| **纯文本（永久）** | 转录稿、课件抽出的文字（`slides/*.json`）、笔记、简报、课次状态 |
| 视频 / 音频 | 只在**转录稿存在、>500 字节、且 sha256 与转录摘要记录一致**时删除 |
| PPT / PDF 原件 | 只在**已抽出文字、页数 >0、文字 ≥20 字**时删除 |
| 校验不通过 | 一律保留，并说明原因（"宁可占盘，不可丢原件"） |

实测：当前 4.0 GB 媒体因为"还没有转录稿"全部保留——这正是设计要的行为。

## 四、结论

**主链路闭环**：六个阶段都能跑通，失败有去向、有人工恢复手段；
付费类故障（欠费/额度/密钥）会翻译成可行动的中文并推微信；
余额可查；课次卡住会停下并通知。

**因此可以开始做前端。** 前端顺序建议：

1. **笔记侧**（公开）：目录侧边栏 + 阅读进度高亮 + 课程索引 + 站内搜索 + 简报卡片。
2. **管理侧-材料**：课件上传（拖拽 + 手机）、归属选择、_unassigned 归类。
3. **管理侧-任务**：各阶段一览、单课次重跑/重置、通知队列与重发、余额卡片（含充值按钮）。
4. **管理侧-配置**：模型与角色、成本窗口、篇幅预算、切片与写作单元数、并发，全部表单化。

前 3 项做完，"每天两次自动跑 + 微信报告 + 手机上传课件"这条日常操作链就完全不需要命令行。
