### 9. MCP —— ✅ 执行验证（真实 MCP over HTTP + 桩控制面）

桩控制面用**和站点同一个 signing key** 校验 HMAC，并记录每次调用的 owner；两个账号的私有内容不同：

| 场景 | 结果 |
|---|---|
| 不带 token | **401** `需要有效的个人 MCP 访问令牌` |
| 用别的 key 签的 token | **401** |
| 已过期 token（40 天前签发，TTL 30 天） | **401** |
| owner A 的 token | 200，`initialize` 成功 |
| member B 的 token | 200，`initialize` 成功 |
| `tools/call list_courses`（A） | 只含 A 的课程「课程甲」；**不含** B 的「课程乙」 |
| `tools/call list_courses`（B） | 只含 B 的「课程乙」；**不含** A 的「课程甲」 |
| 桩控制面看到的 owner | 只有 A/B 两个 UUID，且**全部签名校验通过**（说明 owner 来自 token 的 `sub`，不是请求参数） |

token 实现：HMAC(envelope) 带 `sub/role/iat/exp`，TTL 30 天（`apps/site/src/admin.mjs:46-47,110-125`），scope 前缀 `course-mcp-v1` 与 session `course-session-v1`、SSO `course-sso-v1` 分离 ✓，比较用 `timingSafeEqual` ✓。
`/api/account/mcp-token` 只用**服务端 session** 的 `sub` 签发（`admin.mjs:2020-2029`），浏览器改不了别人的主体 ✓。
