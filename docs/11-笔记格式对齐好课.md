## 2. 那套格式长什么样（成品实测）

以 `国际法学/第1课.md` 为例：19,227 字（去空白），h2=3、h3=12、加粗 319 处、星级 30 处、
表格 88 行、引用块 31 行。骨架：

```
# 课程名 — 第N课
## 课程概览
### 本课要回答的核心问题   （3—5 个理解类问题）
### 本课你应当能够         （- [ ] 可验证目标）
### 课程脉络               （引用块，一段话说清主线）
***
### 一、话题（h3，一级话题）
  [本部分总结：2—3 句]
（一）小节 ★★★            ← 加粗行，不是标题
  正文：短段落 + 表格 + 列表
  > 老师强调：…
  > ⚠️ **易混提醒**：…
  > 💡 **理解难点**：…
  > **自测**（合上笔记，能回答吗？）1… 2… 3…
***
## 附录：补充与发散      （术语汇总表 + 发散话题）
## 知识连接              （承接什么 / 为后续铺垫什么 / 下节预告）
<details>笔记元数据</details>
```

关键是三条：**目录只到话题一级**（小节用加粗行，层级浅所以看得出结构）；
**提示随正文就地出现**（老师强调/易混/难点三种引用块，而不是攒到文末）；
**顶部只有一个「课程概览」块**，不摆一堆并列的装置。

## 3. 我们改了什么

| 位置 | 之前 | 现在 |
|---|---|---|
| 顶部 | 五个并列 h2：本课在课程中的位置 / 知识地图 / 体系线索 / 核心问题 / 学习目标 | 一个 `## 课程概览` + 三个固定 h3；知识地图收进 `<details>` |
| 正文层级 | 四级标题（h4）承载小节，目录长成一棵树 | 小节改成加粗行（`boldBodyHeadings`），目录只到 h3 |
| 复习层 | 文末再加一块「复习层」：概念/法条/案例索引表 + 易错点汇总表（实测 3—5k 字） | 整块取消：索引交给站点的概念/法条/案例页，易错点交给正文里的 ⚠️ 块 |
| 写作规范 | 未要求引用块与星级 | 提示词写明三种引用块的就地写法、案例「论证意义」必须单独写、小节标题带星级、单段 ≤300 字 |
| 体检工具 | 按旧结构验收 | 结构项改为课程概览/核心问题/应当能够/课程脉络/小节加粗/自测/知识连接；新增「没有任何三类引用块」告警 |

## 4. 已有笔记不用重跑模型就能换格式：`tools/reassemble-note.mjs`

成品的**结构**由拼装代码决定，跟正文内容无关；而节点草稿与接缝段数据都躺在
`lesson-state.json` 里（`lesson.nodes[].draft`、`lesson.finalNote.assembly.spliceData`）。
所以改完排版不必重跑模型：

```bash
node tools/reassemble-note.mjs <lesson-state.json> [...] --write   # 默认只报告差异
```

2026-09-26 用它对 6 篇已发布笔记做了一次：h2 从 8—99 降到 3—4、h4 全部归零、
字数普遍下降 2—4k（去掉的正是索引表与重复的装置层），**零模型调用**。
随后 `course publish --from <目录> --no-notify` 逐篇更新站点（`--no-notify` 是这次新加的：
换排版时内容确实变了，但每篇都推一条对读者是骚扰）。

## 5. 还差什么

重拼只能改结构，改不了正文写法。要让三类引用块、星级、案例「论证意义」齐备，
需要用新提示词重新生成。2026-09-26 用新规则重跑了一节（刑事执行法 2026-09-21）作对照：

| 指标 | 旧版（重拼） | 新版（重新生成） | 参考成品（国际法学 第1课） |
|---|---|---|---|
| 字数（去空白） | 15,003 | 18,751 | 19,227 |
| h2 / h3 / h4 | 3 / 15 / 0 | 3 / 16 / 0 | 3 / 12 / 0 |
| 老师强调 / 易混提醒 / 理解难点 | 0 / 0 / 0 | 2 / 1 / 4 | 引用块 31 行 |
| 星级标记 | 0 | 64 | 30 |

结论：结构可以零成本对齐；引用块与星级必须重新生成才会出现。
