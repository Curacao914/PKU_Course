### 阻断项（唯一）

**`deploy/release.sh:128-137` 的 control 分支在校验失败时没有清理 release 目录**，导致新用例断言 `releaseDirs(box) === []` 失败：

```
✖ control 单元缺少 loopback/cgroup 保护：切换前拒绝；恢复真实约束后可发布
  AssertionError: 拒绝发布后不得留下 release 目录
  + actual: [ '20261003-131658' ]   - expected: []
  ℹ tests 701 / pass 700 / fail 1
```

- **原因**：`fail()` 只打印并 `exit 1`（`release.sh:41`），不做清理；而同文件中另外两条同类失败路径都会先 `discard_target; record_failure …`（缺单元路径 `:124-127`、site/admin 角色不符路径 `:141-145`），
  这也正是文件自己的注释所声明的约束（`release.sh:100-103`：「一次没切换成的 release 目录不该留在 `/releases 里」）。四条 `grep -q … || fail` 都缺这一步。
- **影响**：生产正确性不受影响（符号链接未切换、`.history` 未写、回滚不受影响），只是 ``/releases` 里留下一个无用目录且 `.history-failed` 少一条记录 —— 属清理与一致性缺陷；但它让**分支测试变红**，按既定合并门槛必须修。
- **最小修法（我已实测有效）**：在 control 分支的每次 `fail` 之前先 `discard_target` + `record_failure`。我在临时 worktree（`/tmp/a24/pku-fix`，**未写入分支**）按下面这样改完后：

```sh
    if [ "$expected" = "control" ]; then
      control_guard() { discard_target; record_failure roles "$2"; fail "$1"; }
      grep -q '^KillMode=control-group$' "$unit" ||
        control_guard "$name 必须使用 KillMode=control-group；请先重跑 deploy/install-units.sh" "$name 缺少 KillMode=control-group"
      …四条同理…
```
  ```
  修前：ℹ tests 8 / pass 7 / fail 1
  修后：ℹ tests 8 / pass 8 / fail 0
  全量（同一 worktree）：ℹ tests 701 / pass 701 / fail 0
  ```
- **另一条可行但次优的修法**：放宽该断言（允许留下目录）。不推荐 —— 与同文件其它失败路径的行为不一致。

### 不阻断的 Low（本轮新增）

`owner-migration-status.js` 用对象字面量做查表，继承了 `Object.prototype`：Node 实测
```
ownerMigrationNotice('constructor' | 'toString' | 'valueOf' | 'hasOwnProperty') -> function
ownerMigrationNotice('__proto__')                                          -> object
```
于是 `/desk/settings?owner_migration=__proto__` 会把一个对象当作 React 子节点渲染（React 18 对对象子节点是抛错路径），最坏情况是该用户**自己这一次**的设置页报错；
不涉及越权、不涉及他人数据、不影响合并。一行修法：
```js
return Object.prototype.hasOwnProperty.call(messages, key) ? messages[key] : ''
```
（或改用 `Map` / 显式 `typeof === 'string'` 判断。）建议与上条 M3-1 一起顺手改掉，不单独阻断。
