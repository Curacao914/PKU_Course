## 一、当前总体状态

课程笔记系统已经从“流水线能跑”推进到“内容生命周期基本闭环”。

当前目标链路：

```text
教学网录播 / 用户课件
        ↓
转录 + 单课笔记
        ↓
正式正文 revision（唯一事实版本）
        ├── brief
        ├── onepage
        │    └── sourcemap
        ├── metadata / 概念 / 法条 / 案例索引
        ├── configured chapter integrations
        └── semantic embeddings
                ↓
       完整 staging snapshot
                ↓
       全量校验
                ↓
       原子切换 site symlink
```

核心原则已经固定：

1. 单课正式正文是事实源。
2. 所有派生产物都必须与正文版本绑定。
3. 发布必须是完整快照校验后原子切换。
4. 章级整合的“课次范围”由人第一次明确确认，之后系统自动维护，不让 AI 自行扩张章节范围。
5. 历史正文修订前必须先解决 replay 本地源、lesson-state 与正式正文的基线一致性。

### PR #3 已实现

新增三方源一致性模型：

- 正式正文：`site/library.json -> record.markdown`
- 可再发布源：`replays/<replayKey>/transcript/<课次>.md`
- 流水线状态：`lesson-state.json -> lesson.finalNote.markdown`

状态：

- `fresh`
- `source-missing`
- `source-state-drift`
- `unpublished-change`
- `untracked`

新增保护：

- 对已发布课次，如果 `note.md != lesson-state.finalNote`，普通 `publish --from` 默认硬停。
- 这是为了防止 replay 目录残留旧稿，一次 republish 把正式站已经修过的内容覆盖回来。
- `--allow-source-drift` 仅作为明确人工绕过，不是正常流程。

新增命令：

```bash
course source-sync \
  --replay-key <键> \
  [--course <课程>] \
  [--lesson <课次>] \
  --yes
```

作用：

- 以当前正式发布正文作为新的历史修订基线；
- 先完整备份旧：
  - note.md
  - lesson-state.json
  - notes-run-summary.json
- 备份位置：
  `~/.course-worker/source-sync-backups/<时间>/<replayKey>/`
- 再把：
  - note.md
  - lesson.finalNote.markdown
  对齐到正式正文；
- 不调用模型；
- 不发布；
- 不通知。

`reconcile` 也已经接入三方源漂移检查。

相关新增测试均通过。

因此 09-21 当前四象限错误可以确定为笔记整理错误，**不属于待核的教师原话不确定性**。

下一步修 09-21 时，可以安全按以上四项改正，并解除与这四项本身有关的“个别模式名称待核”。

### 2. 刑事执行法 2026-09-14：重复自测块

replayKey：

```
replay-56a9742190482aab0a1b6876
```

多处小节结尾连续出现：

- 第一组 `**自测**`：更细、更开放；
- 第二组 `**自测**（合上笔记……）`：更标准化，并带答案。

- 第一组往往信息更细；
- 第二组有参考答案。

推荐修法：**合并去重**，保留信息量较高的问题，同时保留一套可折叠答案。

### 09-21

- replay Markdown
- lesson-state.finalNote
- library markdown

主要差别来自标题层级 / 展示规范化。

### 09-14

三份差异更大，包含历史模板演进：

- “课程概览”版本
- “本课在课程中的位置 / 体系线索”版本
- 知识地图折叠方式
- 自测装配变化等

所以以后**不能**把“任何字节差异”直接等同于事实错误。

真正危险的是：

```
publish 实际读取的 note.md
    !=
lesson-state.finalNote
```

因为这表示“本地流水线自己都不知道哪份是最新”。

这就是 PR #3 的保护对象。
