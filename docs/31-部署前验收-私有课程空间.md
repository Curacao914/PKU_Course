### 三个部署前必须闭环的缺口

1. **改动集尚未提交**（工作区 44 个文件处于未提交状态）。发布流程是 rsync 工作树 → ``/course-staging` → `deploy/release.sh`；发布元数据只记 `digest`，不记 git 版本。**建议先提交再发布**，否则线上跑的是一份无法复现的树、也难回滚到"上一个已知版本"。
2. **OWNER ``/.course-worker/env` 缺三个键**：`COURSE_CONTENT_VISIBILITY=private`、`COURSE_ACCOUNT_OWNER_ID=<OWNER 的 profiles.id>`、`COURSE_CONTROL_LOCAL_URL=http://127.0.0.1:3102`（`COURSE_CONTROL_SIGNING_KEY` 已有 ✓）。
   **顺序很重要**：新 unit 里写死了 `Environment=COURSE_CONTENT_VISIBILITY=private`，一旦部署 unit，公开站点立刻切私有；而此时 worker 侧若读不到这个键（`commands.mjs:1416`），OWNER 的 publish 仍只写旧 site/library、**不会**写进个人空间 → 结果是"站点藏起来了，个人空间里也没有"。
   → **正确顺序：先补 OWNER env → 再部署 unit/nginx → 再做导入。**
3. **nginx 尚未更新**：线上 `/etc/nginx/sites-available/course` 里 `/api/account/` 与 `/mcp` 的出现次数都是 **0**（预期，属部署步骤）。

另外一条**既有**运维缺口（与本特性无关，但部署时会一起看见）：`course-control.service` 是 `active` 但 `is-enabled = disabled`——机器重启后不会自动起来。建议部署时顺手 `systemctl --user enable course-control.service`。
