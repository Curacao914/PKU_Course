# 模块化方案：course.law-tech.dev

目标：把「教学网下载 → Paraformer 转录 → AI 撰写笔记 → 发布链接 → 微信推送」从 my-blog-main 里摘出来，做成一套**跑在一台服务器上、每个环节都能手动配置和手动运行、同时有对外阅读页**的独立系统。

前置事实见 `00-现状核查.md`。本文只讲目标形态与迁移顺序。

## 一、设计原则

1. **一条链路只有一个实现**。现状里 prompt/模型调用有三份拷贝（`aiAdapter.js`、`run-job.js`、`model-exec-local.js`），模型环境变量有两套契约。新系统只留一份。
2. **纯逻辑与 IO 分离**。纯逻辑（状态机、解析、键计算）不碰网络/文件/进程，可零依赖测试；IO 通过注入传入，便于在服务器与本机之间切换。
3. **每个环节都能单步执行**。所有能力既是定时任务的一步，也是一条可以手动敲的命令，管理台按钮调用同一条命令。
4. **一切状态落在一处，且可读**。用一个 SQLite 文件做账本，人类可直接 `sqlite3` 查看，不引入外部数据库服务。
5. **不长期保存课程视频**。转写完即删媒体，只留转录、笔记与来源定位。

## 二、目录结构

```
course.law-tech.dev/
├── packages/
│   ├── core/         领域模型 + 状态机 + 契约（纯函数，零 IO）
│   ├── acquisition/  教学网采集：登录 / 发现 / HLS 下载 / ffmpeg 合并
│   ├── asr/          Paraformer 转录（Python；boto3 + ffmpeg + R2 中转）
│   ├── notes/        AI 撰写：大纲 → 分节 → 独立审查 → 修订 → 拼装 → 终审
│   ├── store/        账本：任务 / 租约 / 版本 / 投递（SQLite）
│   ├── publish/      站点内容生成（Markdown + 索引）
│   └── notify/       推送：relay 内核 + 本机队列消费
├── apps/
│   ├── worker/       CLI 与定时循环（discover / media / notes / publish / notify）
│   └── site/         course.law-tech.dev：对外笔记阅读 + 私有管理台
├── deploy/           Dockerfile / systemd units+timers / env 样例
├── docs/
└── .reference/       只读参照：my-blog-main 的浅克隆（不入库）
```

## 三、模块契约

### 采集 `acquisition`

沿用现有五步 adapter 契约（`pipeline-adapter-contract.mjs` 已提供校验函数），接口不变：

```js
{
  discover(input)      // → { courses: [{ courseKey, courseName, recordings: [{ replayKey, title, startsAtText, teacher }] }] }
  download(task)       // → { mediaPath, durationSeconds, checksum, streamTypes, loginMode }
  buildTextpack(input) // → course-textpack.v1
  cleanup(task)        // 删媒体与分片，保留转录与 TextPack
}
```

需注入：`browserFactory`、`fetchImpl`、`execFile`/`ffmpegPath`、`scratchRoot`、`profileDir`、`credentials`、`log`、**`selectors`**（现在「当前学期课程」「课堂实录」「观看」等中文字符串硬编码在函数体内，应外提为平台档案，教学网改版时只改一处）。

必须保留的安全不变量（行为契约，不是实现细节）：`assertNoSecrets`、`assertStateHasNoSecrets`、`redactText`、`assertNoInputValues`——丢了会把 URL 与凭据写进 state.json、日志与报告。

### 转录 `asr`

```js
interface TranscriptionProvider {
  transcribe({ audioPath, language, onProgress }): Promise<{
    sentences: [{ beginTime, endTime, text }],
    text: string, transcriptPath: string, costCny: number, provider: string
  }>
}
```

- 首选实现：Paraformer-v2 + R2 预签名中转（现有代码，需剥离 `asr_core.main()` 那段交互式遗留 CLI，requirements 收缩到只剩 `boto3`）。
- 预留第二实现：通义听悟（本机 `~/.claude/skills/haoke-notes/optional/tingwu/` 已有可用脚本，走 `tingwu.cn-beijing.aliyuncs.com` v2 API，AK/SK 签名，能额外给出「口语书面化」与 PPT 关键帧提取）。接口一致即可随时切换。
- 预算保护沿用 `asr-budget.mjs`（按 replayKey 幂等记账，任务级/日级秒数与金额上限）。

### AI 撰写 `notes`

现状的两层队列合并为一层：`store` 里每行就是一个可领取的写作任务，行级租约，不再把租约塞进 JSONB blob。

- 角色：`outline / outlineRepair / writer / reviewer / revision / finalRevision / splicer / finalReview`（现有 `ROLE_SYSTEM` 十段中文提示词直接搬）。
- 模型调用统一为一份 `callModel({role, prompt, signal, config})`，OpenAI 兼容 `/chat/completions`，保留现有 JSON 容错解析（去 think、代码围栏、平衡括号、裸控制符、尾逗号）。
- 角色→模型映射改为运行时注入（现状 `DEFAULT_COURSE_SPEC.models.*` 在模块加载时读 env，抽包时必须改，否则无法按账号切换模型）。
- **关键收益**：不再受 Vercel 函数 300s / 批内 210s 预算约束，长讲座可以一次跑完。

### 账本 `store`

```sql
tasks(id, replay_key UNIQUE, course_key, title, starts_at, teacher,
      stage, attempts, artifacts_json, last_error, next_attempt_at,
      claimed_by, lease_expires_at, heartbeat_at, created_at, updated_at)
lessons(id, task_id, lesson_order, lesson_key, title, status, stage)
notes(id, lesson_id, kind, version, markdown, checksum, state)
deliveries(id, dedupe_key UNIQUE, purpose, body_text, object_url,
           status, attempts, external_id, scheduled_for, sent_at)
```

- **实现用 Node 内置的 `node:sqlite`**，不引入 `better-sqlite3` 这类需要编译的原生依赖——多一个原生依赖就多一处部署可能失败的地方，而服务器与本机都是 Node 24。
- 阶段枚举沿用现有语义（`discovered → queued → downloading → … → published → notifying → completed`，终态为 `failed | needs_attention`）。
- 幂等：`replay_key` 唯一约束；推送用 `dedupe_key` 唯一约束（同一课次不重复发通知）。
- 全部写入走事务与行级租约，避免现状 JSONB 读-改-写的丢更新。

### 发布 `publish`

现状的发布要写 `content_items/versions/access/display` 四张表、推 Algolia、再 `res.revalidate()` 五个路径。新系统简化为：生成 Markdown（带 front matter）+ 更新索引，站点直接渲染。

保留现有 `slug` 规则（`notes/<course>/lesson-N`）与元数据字段，方便未来回迁或并行运行。

### 推送 `notify`

- 通道：复用现有 OpenClaw relay 内核（`normalize-message`、`base-url`、`law-tech-client`、poller 纯函数，21 个测试全绿），发送动作仍是 `spawn openclaw message send --channel openclaw-weixin --target <target>`。
- 唯一改动：队列来源从「轮询 Vercel 的 prepare/claim/ack」改成本机读账本——因为现在 relay 与 Gateway 已经同机（腾讯云 user systemd），不需要跨公网。
- 顺手修掉已定位的确定性缺陷：base URL 的 4 套不一致逻辑（统一走 `normalizeLawTechBaseUrl`）、默认域名两套、`target_key` 入库却不被消费、manifest 与 package.json 版本漂移、`plugin.js` pending 可能错配消息。
- 每日推送内容：当天更新的笔记链接汇总，长度受控，同一课次不重复。

## 四、运行形态

```
腾讯云 124.222.111.108（唯一常驻机器，Mac 不参与）
├── course-worker.timer   → 定时：发现新回放 → 下载 → 转录 → 写笔记 → 发布 → 排队推送
├── course-site.service   → course.law-tech.dev（对外阅读 + 私有管理台）
├── OpenClaw Gateway      → 已有，不动
├── Cloudflared           → 已有，不动
```

**手动运行**：同一批命令两种入口——命令行 `course discover|download|transcribe|notes|publish|notify`，以及管理台按钮（调用同一命令，展示进度与日志）。

## 五、迁移顺序与验收门槛

每一步都必须**独立可用**，且带可执行的验收条件。

| 步骤 | 内容 | 验收 |
|---|---|---|
| 0 | 仓库骨架、契约定义、CI | 空壳可构建 |
| 1 | `core` + `acquisition` + `asr` | **搬来的 61 个单测全绿**；真实跑通一节课：下载 + 转录 + 删媒体 |
| 2 | `store` + `worker` CLI | 同一节课重复运行不产生重复任务；中断后可续跑 |
| 3 | `notes`（收敛为一份实现，后台 worker 化） | 一节真实课跑完整大纲→节点→审查→拼装→终审；不再有 210s 天花板 |

**步骤 3 进展（2026-09-25）**：已搬入 `packages/notes` 的三块纯逻辑，共 37 项单测：

| 模块 | 内容 | 单测 |
|---|---|---|
| `ai-adapter.mjs` | 十段中文角色提示词、请求组装、容错 JSON 解析、调用追踪与错误分类 | 17 |
| `llm-schedule.mjs` | 成本窗口闸门（economy 避峰 + 边界缓冲 + 跨午夜窗口） | 10 |
| `worker-tasks.mjs` | 从工作流状态推导下一步该做什么（含上游阻塞、修订上限、审查并发） | 10 |

三处改进：env/fetch 可注入（测试不需要网络与凭据）；超时上限不再被 Vercel 的 240s 硬截断；时区名写错原本会在深处抛 `RangeError`，现在归一化阶段就回落默认值。

**步骤 3 续（2026-09-25）**：从 1244 行的 `workflowState.js` 中摘出真正决定质量的四件事，做成不可变的纯函数 `node-lifecycle.mjs`（21 项单测）：

| 能力 | 语义要点 |
|---|---|
| 大纲覆盖校验 | 必须从第 1 行起、无缺口、无尾巴——"笔记不能漏讲"是硬约束 |
| 节点确定性切分 | 字符数与行数双阈值；同输入必得同边界，这是断点续跑的前提 |
| 审查判定 | 分数下限是 `max(45, 阈值-20)` 而非阈值本身；blocking 问题优先于分数 |
| 状态迁移 | 版本不匹配的审查不算数；修订次数用尽后带警告放行；只有 `impact=downstream` 的问题才阻塞后文 |

未搬走的是原文件里面向 Web 工作台的步骤条、进度百分比与人工审批门禁——那些属于界面，不属于流水线。

**尚未搬入**：`runBatch/onlineRunner`（批次编排与八种角色执行器）与 `assembleFinalNote`（机械拼装）。
| 4 | `publish` + 站点阅读页 | 笔记出现在 course.law-tech.dev 上，链接可直接打开 |
| 5 | `notify` | 微信真实收到一条笔记链接；同课次不重复发 |
| 6 | 管理台 + 定时器 | 关掉全部手动操作，连续运行数天无静默漏课 |

步骤 1 是**风险最低、收益最早**的一块：它零 `lib/` 依赖、零外部服务（除 ASR 与 R2）、有现成测试基线，搬完立刻可以脱离整个旧系统独立使用。
