# 0001 学期后缀年份位数兼容两位与四位

日期：2026-09-24
状态：已采纳

## 背景

搬运 `platform-core.mjs` 时补写单测，发现同一文件里两个函数对学期后缀的匹配宽严不一致：

- `normalizeCourseName`：`/[（(]\s*\d{2}-\d{2}学年第\d学期.*?[）)]\s*$/`
- `parseCourseLabel`：`/[（(]([^()（）]*?学年第\d学期[^()（）]*)[）)]\s*$/`

前者要求两位年份（`25-26`），后者不限位数。真实教学网标签形如 `00412-张老师：国际法学（2025-2026学年第1学期）`，四位年份。因此：`normalizeCourseName('国际法学（2025-2026学年第1学期）')` 返回原串，后缀未被剥除。

## 影响范围

生产链路**未受影响**：`parseCourseLabel` 用自己的宽松正则剥掉后缀后再调 `normalizeCourseName`，所以课程名仍是干净的。该缺陷只在直接对原始标签调用 `normalizeCourseName` 的路径上显现（如 `name` 为空时的回退分支），属于潜伏不一致。

## 决定

在搬运版中把年份改为 `\d{2,4}` 并放宽学期序号为 `\d+`：

```js
.replace(/[（(]\s*\d{2,4}-\d{2,4}学年第\d+学期[^()（）]*[）)]\s*$/u, '')
```

理由：该函数的职责就是剥除学期后缀；放宽只会让"本应剥除却没剥"的情况变正确，不会破坏已正确的路径。

## 验证

`packages/acquisition/src/platform-core.test.mjs` 中同时断言两位与四位年份两种形式。

## 后续

拿到真实课程标签样本后应补一条夹具测试，确认无其他后缀形态（如"秋季学期""第1-2学期"）被漏掉。
