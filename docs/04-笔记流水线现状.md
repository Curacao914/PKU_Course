## 4. 确认点

机器确认（每课必然发生）：

1. 大纲连续覆盖校验（`assertOutlineCoverage`）
2. 每个节点一次独立审查（阈值 75；分数下限 `max(45, 阈值-20)`）
3. 拼装完整性 + 无占位符校验
4. 终审

人工入口（目前**没有任何东西会自动触发它们**）：

- `requestNodeRevision`（`node-lifecycle.mjs:415`）：人工提修订要求
- `approveNodeHuman`（`node-lifecycle.mjs:431`）：人工放行，必须写理由
- 大纲确认门（`pipeline.mjs:70`）：设 `autoApproveOutline=false` 才会停

## 5. 审查与放行规则（容易看错的四条）

1. 分数下限是 `max(45, 阈值-20)`，不是阈值本身。
2. 审查报告必须对应当前草稿版本，否则视为未审查。
3. 自动修订次数用尽后是"带警告放行"（`autoAcceptedWithWarnings`），不是永久卡住。
4. 只有 blocking / 需人工 **且** `impact=downstream` 的问题才阻塞后文节点；上游通过后下游自动重查（`consistencyRequests`）。

终审四条出口（`node-lifecycle.mjs:496-585`）：能定位到节点→退回该节点修订；定位不到→整篇修订（`maxFinalAutoRevisions=1`）；预算用尽→带警告放行；通过→`completed`。
