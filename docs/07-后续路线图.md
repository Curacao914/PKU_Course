# 07 · 后续路线图：材料（PPT）、自动化、前端

> 记录时间：2026-09-25。用户明确说"现在还没到时候，但后面要记得做"。
> 本文是承诺清单与设计结论，不是已完成项。已完成项见 docs/04 与 docs/06。

## 一、课件（PPT）进流水线

### 1.1 为什么必须做

三件事都指着它：

1. **ASR 对照**：转写稿里"卫监/位阶"这类听错的专业词，靠课件上的原文才能确定（调研 §M10 的
   ASR 更正表就需要这个依据）。
2. **结构对照**：旧手工流程的大纲骨架就是按 PPT 展开的；课堂口语顺序与课件结构常常不同，
   两者对照才能既按知识体系、又不漏讲。
3. **可核对性**：笔记里能写"依据第 4 讲课件第 12—15 页"，复习时能回去对。

现状：`createInitialLesson` 与 `pptForRange` 早就支持 `pptText`/`slideRange`，
但 CLI 从来没传过 PPT，所以这条通道是**空转**的。

### 1.2 上传方式：四个选项与建议

| 方案 | 怎么用 | 便利性 | 代价 | 建议 |
|---|---|---|---|---|
| **A. 管理台上传** | 管理页里按课次拖拽上传 pptx/pdf | 高（手机浏览器也能传） | 需要在站点服务器实现一个无依赖的上传端点（`PUT /api/admin/materials?course=&lesson=&name=` 直接收原始 body，管理页用 fetch 发送） | **兜底方案，推荐先做** |
| **B. 收件箱目录** | 把文件丢进 `~/.course-worker/inbox/`（SFTP/scp），文件名含课程与课次 | 中（要装 SFTP 客户端） | 几乎为零，一个 ingest 命令按文件名归档 | 与 A 并行，脚本化时好用 |
| **C. 同步盘** | Syncthing / Nextcloud 把 Mac 的课件目录同步到服务器 | 高（一次配置长期省事） | 多一个常驻部件与同步冲突风险 | 备选 |
| ~~D. 从教学网自动抓~~ | ~~发现新课顺带下载课件~~ | — | — | **已否决（2026-09-25 用户确认）：教学网上没有课件，课件只在用户手里** |
| E. 邮件/微信投递 | 把文件发给机器人 | 中 | 部件多、易碎 | 不做 |

**结论（2026-09-25 修正）：教学网没有课件可抓，因此走 A + B——管理台上传是主路**
（手机浏览器也能传），收件箱目录是脚本化的备选。两条路都落到同一份归档与解析流程。

### 1.3 归档与解析

- 归档：`~/.course-worker/materials/<courseKey>/<replayKey>/`，元数据（文件名、类型、sha256、
  上传时间、页数）写进课次状态。
- 解析 pptx：**不引依赖**。pptx 就是 zip + XML，用 Python 标准库 `zipfile` + `xml.etree`
  按 `ppt/slides/slideN.xml` 顺序抽文字即可（现有 ASR 侧已经只用标准库，风格一致）。
  pdf 用 `pdftotext`（服务器已有 poppler 的话）或留到以后。
- 产物：`slides.json`（[{slideNumber, text}]），喂给 `lesson.pptText`。

### 1.4 提醒机制

发现新课之后，如果该课次还没有课件，就排一条通知：

> 【法学课程】发现新课：法律实证分析 · 2026-09-30第3-4节
> 这一节还没有课件。上传 PPT 能显著提高笔记质量：术语能对齐、结构能对照。
> 上传入口：https://course.law-tech.dev/admin （或把文件放进收件箱目录）

用户回"无课件"可以免打扰（记一条 `materialsWaived` 标记）。

## 二、自动化

### 2.1 现状

- `course-cycle.timer` 目前**停着**（结构定稿前不让它自动跑其余 15 节课）。
- 谷价顺延已实现：写笔记前查成本窗口，峰段顺延、零调用、账本退避到窗口开启时间。
- 转写不限时段（用户明确"转文字无所谓"）。

### 2.2 目标形态

| 项 | 设计 |
|---|---|
| 检测频率 | **每天两次**：07:30 与 19:30（北京时间）。07:30 在峰段之前、19:30 在谷段 |
| 检测内容 | 登录教学网 → 登记新回放 → 排入下载/转录 |
| 写笔记时机 | 由成本窗口自动决定：遇峰段顺延到 12:10 / 18:10 |
| 转写时机 | 任何时间 |
| 失败可见性 | 连续失败的课次进 `needs_attention`（现在这个终态是死代码，要接上）并在通知里报出来 |
| 幂等 | 同一课次重复检测不产生重复任务（已实现） |

### 2.3 要补的接线

1. 定时器改成 07:30 / 19:30 两次（现在单元文件写的是 08:20/14:20/20:20）。
2. `needs_attention` 真正产生：同一阶段连续失败 N 次后置位，并排通知。
3. 每日汇总通知（可选）：今天处理了几节课、哪些还在等材料。

## 三、前端

### 3.1 笔记侧（公开，谁都能看）

目标：**可读性优先**，长文能读得下去。

| 要做的 | 具体形态 |
|---|---|
| 目录侧边栏 | 章节树固定在左侧，**随阅读进度高亮当前小节**（IntersectionObserver），点击平滑滚动；窄屏折叠成顶部按钮 |
| 阅读进度 | 顶部或侧边一条细进度条 |
| 排版 | 已有衬线正文；再补：引用块/表格/图表的间距统一、代码与公式、`<details>` 折叠样式、打印样式 |
| 简报固定 | 本课简报做成页首卡片，滚动后收成小条（"这节课在讲什么"随时可看） |
| 课程索引页 | 按课程分组的目录页 + 站内搜索（现在是全量静态 JSON，搜索可以纯前端做） |
| 图 | Mermaid 已自托管按需加载；再加图注与"图源"折叠 |

实现成本都不高：站点是零依赖的原生 Node + 手写 Markdown 渲染器，侧边栏+滚动高亮大约几十行 JS。

### 3.2 管理侧（只有我能看）

目标：**结构化**，不要一堆按钮散在那里。分区块，每块一个职责：

| 区块 | 内容 |
|---|---|
| 概览 | 各阶段任务数、最近一次运行摘要、磁盘与凭据状态 |
| 课程与课次 | 课次列表、当前阶段、产物链接、手动推进/重试/标记无需处理 |
| 材料 | 每课次课件的上传与替换、解析状态（对应 §一） |
| 笔记 | 逐模块预览、**只重写某模块**（对应 `--revise`）、重新拼装/重发通知 |
| 通知 | 投递队列、重发、静默某课次 |
| 运行 | 手动触发各命令（已有）、定时器开关与下次运行时间 |
| 配置 | 模型与角色映射、成本窗口、篇幅预算、切片与写作单元数、并发 |
| 日志 | 最近 N 次运行的摘要与错误 |

配置一律**表单 + 校验 + 落盘到 JSON**，不散在环境变量里手改。管理页继续 fail-closed（无令牌拒绝）。

## 四、建议排期

1. **课件（§一）**：先验证教学网能否自动抓（30 分钟），再做解析器（半天），再做上传入口与提醒。
2. **篇幅与局部重写**：已完成（`--target-chars`、`--revise`），等新一轮验收数据。
3. **前端笔记侧**（§3.1）：半天到一天，收益最直观。
4. **自动化两次检测 + needs_attention**（§2.3）：半天，做完就可以把定时器打开长期跑。
5. **管理侧**（§3.2）：分两三次迭代做，优先"材料上传"和"逐模块重写"两块。
