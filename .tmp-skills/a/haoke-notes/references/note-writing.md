# 单课笔记撰写流程

将工作流产出的转录稿 + PPT 文字内容转化为结构化 Markdown 笔记。

## 目录

- 流程总览
- 步骤 A：通读 + 大纲 + 行号映射
- 步骤 B：节点级撰写
- 步骤 B+：节点过大时的细分
- 步骤 C：拼装与定稿
- META 标签：作用与位置
- PPT 辅助 ASR 纠正
- 学习目标定向
- 撰写语言要求
- 完整笔记结构模板
- 质量检查

---

## 流程总览

```
A. 通读全部 segments + PPT → 生成大纲（含每节点的转录起止行号）→ 用户确认
B. 按大纲二级节点逐节撰写（每节一次定稿，写入 working/notes_第N课_node_{id}.md）
B+. 节点对应转录 ≥ 200 行时，按三级子节点再细分一层
C. 按大纲顺序拼装 + 添加概览 + 收纳 META 折叠框 → output/notes/第N课.md
```

按大纲节点切分撰写而不是按行数切分，原因：

- 节点边界 = 结构边界，不会切在概念中间
- 每节是完整单元，写出来就是定稿，C 步骤不做整合性写作（避免触输出上限）
- 全局重要性判断在 A 步骤一次完成，B 步骤继承

撰写在主进程串行完成，不调用并行子 agent。串行最大化 prompt cache 命中（写作规范、PPT、segments 在多课次间共享缓存），既省 token 又保证结构一致性。

---

## 步骤 A：通读 + 大纲 + 行号映射

### A1. 读取输入

依次读取：

1. `working/preferences.json` — 用户问卷答案（学习目标、讲课风格、老师姓名等）。不存在则先按 `references/preflight.md` 完成问卷
2. `data/segments/第N课_segments.json` — 段元数据，确认转录总行数和段数
3. 全部 `data/segments/第N课_segment_M.txt` — 通读完整转录
4. `data/ppt_md/第N课_ppt.md` — PPT 文字内容

### A2. 识别讲授主线

读完后心里要有一条主线。讲授通常遵循某种逻辑展开：

- 概念 → 原则 → 规则 → 适用 → 案例（抽象到具体）
- 历史沿革 → 现行规定 → 学说争议 → 实践问题（过去到现在）
- 理论框架 → 比较法 → 中国法 → 实务问题（一般到特殊）

主线决定笔记的整体结构。

### A3. PPT 与讲授顺序的协调

**以 PPT 为基础框架**。原因：老师讲课节奏不一，可能跳跃、不用 PPT、或一节课用多份 PPT 文件。单纯按老师的意识流顺序，笔记看起来会非常疑惑。

具体做法：

- 大纲骨架 = PPT 主题和逻辑顺序
- 每个节点下的内容填充 = 老师在该话题上**实际讲授的逻辑**
- PPT 上有但转录未涉及的内容 → 标注"PPT 提及但未展开"
- 转录中讲了但 PPT 未显示的 → 仍纳入笔记，归入语义最近的 PPT 节点
- 老师跨 PPT 反复呼应同一概念时，归入概念首次系统讲解的那个节点；其他位置仅做交叉引用（"参见本课第 X 节"）

如果用户问卷中说明老师严格按 PPT 顺序讲解，按 PPT 顺序直接对齐；说明老师发散讲解时，按上述策略以 PPT 为锚重组。

### A4. 识别讲授重点信号

教授会发出明确的"重点信号"：

- "大家注意" / "大家记住" / "这里需要注意"
- "这个很重要" / "非常重要" / "这是一个重点"
- "考试可能会考" / "可能考"
- "所以我们可以总结出"
- "也就是说"（后面通常是对前面内容的进一步阐释或定义）
- "与此类似" / "与此不同"（对比和类比）
- "换句话来说"（同一内容的另一种表述，通常更清晰）

根据信号强度判断重要性等级，标记到对应的二级节点：

| 等级 | 标记 | 判断标准 |
|------|------|---------|
| ★★★ | 核心必掌握 | 老师明确说"很重要 / 会考 / 必须记住"；或贯穿全课反复出现的概念 |
| ★★ | 重要需理解 | 老师花了较多时间讲解，或支撑核心概念的关键铺垫 |
| ★ | 了解即可 | 背景知识、扩展说明、举例性内容 |

### A5. 输出大纲文件

输出到 `working/第N课_outline.json`：

```json
{
  "course_name": "知识产权法",
  "lesson_num": 3,
  "main_thread": "本课围绕著作权客体展开，从作品构成要件到作品类型再到不受保护的对象",
  "ppt_pages_total": 32,
  "transcript_lines_total": 1845,
  "outline": [
    {
      "id": "1",
      "level": 1,
      "title": "一、著作权的客体",
      "transcript_lines": [1, 820],
      "ppt_pages": [3, 4, 5, 6, 7, 8],
      "section_summary": "本部分讲什么是作品，含构成要件、作品类型、不受保护的对象三个层次"
    },
    {
      "id": "1.1",
      "level": 2,
      "parent_id": "1",
      "title": "（一）作品的构成要件",
      "stars": 3,
      "transcript_lines": [15, 380],
      "ppt_pages": [4, 5, 6],
      "concepts": ["独创性", "可复制性", "思想表达二分法"],
      "provisions": ["著作权法第3条", "著作权法实施条例第2条"],
      "cases": ["凤凰网诉天盈九州案"],
      "key_signals": ["老师强调独创性是核心", "明确说会考"],
      "writer_brief": "三要件，重点讲独创性，引用凤凰网案展开'独立完成 + 一定创造性'"
    }
  ],
  "appendix_topics": [
    {"topic": "课堂管理：调课通知", "transcript_lines": [1820, 1845]}
  ]
}
```

**字段说明**：

- `transcript_lines`：该节点对应的转录行号区间（含两端）。后续 B 步骤按此区间切片读取
- `ppt_pages`：该节点涉及的 PPT 页码（用于撰写时对照纠错和引用）
- `concepts / provisions / cases`：从转录中识别到的关键对象，A 步骤先粗列，B 步骤撰写时确认
- `writer_brief`：给 B 步骤的写作提示（一句话），帮助节点撰写时快速定调
- `appendix_topics`：发散内容（课堂管理、闲聊、时事评论等），单独列出以便 C 步骤归入附录

### A6. 用户确认

向用户输出：

- 本节课内容概述（2-3 句）
- 大纲层级结构（不输出 JSON，输出可读的列表）
- 列出识别到的发散内容，确认归入附录无误
- 针对当前课程的具体疑问（如有）

等待用户确认或调整后，进入步骤 B。如用户对大纲有修改，更新 outline.json 后再继续。

## 步骤 B：节点级撰写

### B1. 撰写策略

按 outline.json 中 `outline[]` 的 level 2 节点顺序，逐个撰写：

```
对每个 level 2 节点：
  1. 读取该节点 transcript_lines 区间对应的转录文本
  2. 读取该节点 ppt_pages 涉及的 PPT 文字内容
  3. 参照 writer_brief 和学习目标，撰写完整笔记
  4. 在节点笔记末尾以行内代码形式列出本节出现的概念/法条/案例/易混点
     （供 C 步骤合并到全文末尾的 META 折叠框）
  5. 输出到 working/notes_第N课_node_{id}.md
```

如该节点对应转录 ≥ 200 行，进入 B+ 流程。

### B2. 节点笔记的内部结构

每个 level 2 节点笔记的格式：

```markdown
（一）[节点标题] ★★★

[内容主体：概念解释、法条引用、案例分析、学说讨论]

> 老师强调：[强调内容，如有]

> ⚠️ **易混提醒**：[易混对比，如有]

> 💡 **理解难点**：[难点说明，如有]

<!-- META 收纳（C 步骤会汇总到全文末尾） -->
META_FOR_NODE:
- CONCEPT: 独创性
- CONCEPT: 可复制性
- PROVISION: 著作权法第3条
- CASE: 凤凰网诉天盈九州案
- PITFALL: 思想 vs 表达
```

末尾的 `META_FOR_NODE:` 块只是临时收纳，C 步骤会读取并合并到全文末尾的折叠框；正文中**不再嵌入** `<!-- META: ... -->` 注释。

### B3. 内容提取与重组

**概念**：

- 提取教授的定义或解释
- 有对比时用对比表格或对比列表
- 标注概念在整个知识体系中的位置

**法条**：

- 标注法律名称和条号
- 提取条文核心规定
- 标注适用范围和条件
- 标注与其他法条的关系

**案例**（每个案例必须包含以下全部要素）：

1. 案件名称 / 背景
2. 案情简介（用简洁的语言概括基本事实）
3. 争议焦点 / 法律问题
4. 裁判结果 / 法律适用
5. 老师的评论或分析
6. **论证意义**（必写）：老师为什么讲这个案例，它对课程主线的论证意义是什么

**学说争议**：

- 列出各方观点
- 列出论据和理由
- 标注通说 / 主流倾向（如有）

### B4. 标记策略

**重点不要过度标记**。只有当老师确实明确强调、反复提及的内容才用引用块标注：

```markdown
> 老师强调：[强调内容]
```

不要在正文中用加粗标记"老师强调"——重点统一用引用块呈现。

**易混点**用 ⚠️ 块：

```markdown
> ⚠️ **易混提醒**：[两个易混概念的对比说明]
```

**理解难点**用 💡 块：

```markdown
> 💡 **理解难点**：[难在哪里，正确的理解角度]
```

三种引用块并列存在，互不替代。

### B5. 章节末自测题

每个一级标题（`### 一、XXX`）的所有子节点写完后，在该一级标题末尾追加自测块：

```markdown
> **自测**（合上笔记，能回答吗？）
> 1. [理解类问题，涵盖本节核心 Why/How]
> 2. [对比类问题，针对本节的易混内容]
> 3. [可选：应用类问题，把本节概念用到具体情境]
```

要求：

- 每节 2-3 题，不超过 3 题
- 题目必须是理解类或对比类，不要出"列举三个要素"这类纯记忆题
- 没有显著理解难点或对比关系时，1-2 题即可

自测块由 C 步骤插入（B 步骤只产出节点本身的内容，不在节点级写自测）。

## 步骤 B+：节点过大时的细分

当某个 level 2 节点对应转录 ≥ 200 行时，B 步骤需要进一步细分以避免单次输出触上限。

### B+1. 二次切分

读取该节点对应的 PPT 页面，识别 level 3 子节点（如「1. 独立完成」「2. 一定的创造性」）。这些子节点通常对应：

- PPT 中的子标题
- 转录中的明显小节切换（"接下来我们看..."、"第二个要件..."）

将该节点的 transcript_lines 按 level 3 子节点进一步划分，更新 outline.json。

### B+2. 子节点撰写

对每个 level 3 子节点，按 B 步骤同样的方式撰写。子节点撰写完成后，在节点内合并：

- 子节点输出到 `working/notes_第N课_node_{id}_sub_{j}.md`
- B+3 合并到 `working/notes_第N课_node_{id}.md`

### B+3. 节点内合并

子节点合并时：

- 检查衔接是否连贯，必要时补一句过渡
- 合并各子节点末尾的 META_FOR_NODE 块
- 保留子节点的 level 3 标题（`1. XXX`、`2. XXX`）

---

## 步骤 C：拼装与定稿

C 步骤是轻量拼装，不做整合性写作。

### C1. 按大纲顺序合并

读取 outline.json 的节点顺序，依次拼接 `working/notes_第N课_node_*.md`。

一级标题（`### 一、XXX`）由 C 步骤插入（B 步骤只写 level 2 节点）。在每个一级标题后、第一个子节点前，用 outline.json 的 `section_summary` 写一段总结（2-3 句）。

### C2. 插入自测块

按 B5 的格式，在每个一级标题的所有子节点后插入自测块。自测题由 C 步骤基于该节内容拟定（C 步骤这时已读到该节全部 B 输出，能拟出针对性的题）。

### C3. 撰写课程概览

笔记最开头的"课程概览"由 C 步骤撰写（此时已读完全部节点定稿，对全课有整体把握）：

```markdown
# [课程名称] — 第N课

## 课程概览

### 本课要回答的核心问题
1. [理解类问题，3-5 个]
2. ...

### 本课你应当能够
- [ ] [可验证的学习目标，动词开头，如「区分」「解释」「列举」]
- [ ] ...

### 课程脉络
> [概括本节课核心主题和讲授脉络]
>
> [体系化列出核心内容节点]

***
```

要求：

- 「核心问题」是理解类问题（Why/How/区别），不是记忆类（What）
- 「应当能够」3-5 个，可验证、不空泛
- 「课程脉络」先用一段话概括，再用列表展开

只在开头放概览，不要在末尾加"课程总结"。

### C4. 整理附录

发散内容（outline.json 的 appendix_topics + B 阶段标记的发散段）归入附录：

```markdown
***

## 附录：补充与发散

> 以下内容为课堂补充材料和发散性讨论，不影响课程主线

### 术语汇总

| 术语 | 英文/原文 | 定义或说明 |
|------|----------|-----------|
| ... | ... | ... |

### [发散话题名称]

[简略概括]
```

术语表收录英文/原文术语和老师明确给出原文的概念（外文专著名、学者名等）。

### C5. 知识连接

```markdown
***

## 知识连接

**承接什么**：[本课建立在哪些前置知识或常识上；若是第一课，注明默认的知识背景]

**为后续铺垫什么**：
- [本课概念A] → [后续课程中的用途]
- [本课概念B] → [...]

**下节预告**：[如转录中有提及]
```

「为后续铺垫什么」是核心，必须写；即使是第一课，也要根据课程体系推断。「承接什么」和「下节预告」如果没有信息来源（转录未提及），可省略或标注「待补充」。

不要加「现实问题连接」和「金句汇编」——这两块质量不稳定。

### C6. 收纳 META 折叠框

读取所有 `working/notes_第N课_node_*.md` 末尾的 `META_FOR_NODE:` 块，去重合并，输出到笔记最末尾：

```markdown
***

<details><summary>📑 笔记元数据（用于跨课整合）</summary>
<pre><code>
META: CONCEPT: 独创性
META: CONCEPT: 可复制性
META: CONCEPT: 思想表达二分法
META: PROVISION: 著作权法第3条
META: PROVISION: 著作权法实施条例第2条
META: CASE: 凤凰网诉天盈九州案
META: PITFALL: 思想 vs 表达
META: PITFALL: 独创性 vs 新颖性
</code></pre>
</details>
```

`<details>` + `<pre><code>` 在 Typora 中默认折叠，不影响阅读连贯性；展开后是普通代码块，渲染稳定。`build_index.py` 用 `re.findall(r'META:\s*(\w+):\s*(.+)')` 全文扫描即可提取，不依赖标签位置。

### C7. 输出

保存到 `output/notes/第N课.md`，删除节点级中间文件 `working/notes_第N课_node_*.md`（保留 outline.json 用于复盘）。

## META 标签：作用与位置

META 标签服务于阶段 3 的全课程整合：

- `CONCEPT`：核心概念清单 → 知识图谱、概念追踪、辨析表
- `PROVISION`：法条清单 → 法条精读表
- `CASE`：案例清单 → 案例练习库
- `PITFALL`：易混对清单 → 辨析表

**位置规则**：

- B 步骤撰写节点时，在节点末尾用 `META_FOR_NODE:` 块临时收纳
- C 步骤合并到笔记末尾的 `<details>` 折叠框
- 正文中**不嵌入**任何 `<!-- META: -->` 注释（Typora 在某些情况下会渲染注释，影响阅读）

**值格式**：

- PROVISION：不带书名号，统一简称。`民法典第215条`（不是 `《民法典》第215条`）
- CONCEPT：准确的概念术语。同一概念在多处出现时只在折叠框列一次（去重）
- CASE：案件名。如有多个名称，选最常用的一个
- PITFALL：`概念A vs 概念B`，固定格式

## PPT 辅助 ASR 纠正

撰写时遇到可疑的法律术语、专有名词、人名时，**先在该节点对应的 PPT 文字中搜索**——PPT 上出现的术语是正确的（PPT 是老师准备好的文字材料，没有 ASR 错误）。

如果转录稿和 PPT 在同一概念上字面不同，以 PPT 为准。

`references/asr-error-patterns.md` 是常见错误参考表，但 PPT 比这个表更可靠：参考表是经验值，PPT 是当节课的实际用词。

只在 PPT 没有提及该术语时，才回退到参考表 + 上下文推断。

## 学习目标定向

`preferences.json` 中的 `learning_goal` 字段决定撰写策略。四种目标的具体侧重：

### 闭卷应试

- 突出重点（★ 等级标记不省略）、老师明确强调的考点用 `> 老师强调` 块
- 课程脉络段尽量精炼，便于快速回忆框架
- 每个核心概念配 1-2 句记忆口诀（如有合适的 mnemonic）
- 自测题偏重应用和对比，模拟考试场景
- 易混点 ⚠️ 块尽量穷尽

### 开卷应试

- 详尽完整不删节
- 笔记内必须有强索引：每个一级标题处加锚点；术语 / 法条 / 案例反复出现时插入"参见第 X 节"
- 法条引用必须含完整条号和分款
- 不需要记忆口诀，但要确保术语和老师措辞精确
- 课程概览的"应当能够"项可以扩展到 5-7 个

### 论文 / 研究

- 学说争议部分加重，列出每位学者的具体观点和理由
- 老师的学术倾向单独标注（"老师赞同 X 说，反对 Y 说，理由是..."）
- 比较法内容（外国法、罗马法、德日学说）保留细节
- 概念辨析倾向于学理边界的精细对比，而非应试性的简化区分
- 文献线索单独列入附录（"老师提到 X 教授的 Y 文章"）

### 自学 / 入门

- 按学习顺序组织，**初次接触者视角**
- 每个新概念前补一句"为什么需要这个概念"
- 减少专业术语的隐式假设，第一次出现时用通俗语言解释
- 案例的"论证意义"段写得更展开，帮助理解概念为什么重要
- 课程脉络段说明本课在全课程中的位置（"这是物权法基础部分的第三课，前两课讲了..."）

如果 `preferences.json` 中没有 `learning_goal` 字段，按"闭卷应试"作为默认。

## 撰写语言要求

### 语言风格

- 学术书面语，不要口语化
- 用"老师指出"、"老师强调"、"老师认为"等引导语
- 老师的观点需要细致记录：论证的逻辑链条、对不同学说的评价倾向、对某个法条适用边界的判断

### 详细程度

- 与课程主线相关的内容详细展开
- 与主线关系较远的内容可以简略
- 但无论简略与否，都不要遗漏必要的信息点

### 可读性与思维连贯性

- 段落之间添加过渡句，使笔记的逻辑流畅
- 每个子主题的内容应当完整且自成一体
- 核心 insight 必须深入讲解——不要只罗列结论，要还原老师的论证过程
- 内容完整性优先：不要因为重构大纲而遗漏任何知识点

### 处理不确定内容

- 根据上下文做出最佳推断
- 无法确定含义时标注 `（转写不清，待确认）`
- 不要编造内容

### Markdown 格式要求

充分利用 Markdown 语法提升可读性和重点突出程度：

- **加粗**：核心概念、关键术语、重要人物名、法条名称。不要整段加粗，只标记关键词
- **引用块 `>`**：老师的强调、原话引用、经典名言、重要结论
- **表格**：对比类内容（不同流派、不同观点、不同定义对比）
- **有序列表 `1.`**：有明确顺序或层级关系的内容（前提假设、演化步骤）
- **无序列表 `-`**：并列罗列的内容
- **行内代码** `` ` `` ：文件名、术语原文、专有名词英文
- **分隔线 `***`**：大章节之间的视觉分隔（用 `***` 而非 `---`，兼容性更好）
- **嵌套列表**：子要点用缩进的二级列表
- **重点标记 `<kbd></kbd>`**：法条号码等需要突出强调的内容

格式服务于阅读体验，不为了格式而格式化。判断标准：读者扫读时能否快速抓住重点和结构。

## 质量检查

撰写过程中关注以下 5 项核心：

1. 课程概览是否准确概括全课内容（C3 完成时检查）
2. 每个一级标题下是否有总结段（C1 完成时检查）


verify_notes 通过即视为定稿。需要主观判断的项（语言学术化、逻辑连贯、不遗漏知识点等）由用户在审阅时把关。

## changelog 自检机制

每课撰写过程中，须在 `.haoke_changelog.md` 维护可打勾的节点级 checklist。此机制用于防止跳步偷懒——任何未打勾的环节都不允许进入下一步。

### 格式

```markdown
## 第N课
| 步骤 | 状态 | 说明 |
|------|------|------|
| Step A: outline | ✅ | 用户已确认 |
| Step B: nodes | 🔄 | 逐节点撰写 |

节点进度：
- [x] B.1.1 node_1.1 (标题, X行)
- [x] B.1.2 node_1.2 (标题, X行)
- [ ] B.2.1 node_2.1 (标题, X行)
- [ ] B+.2.2 node_2.2 (标题, 250行→B+)
- [ ] Step C: assembly + verify
```

### 规则

1. **Step A 完成时**：在 changelog 中写入所有待写节点的 `[ ]` checklist，每个节点一行含行数
2. **每写完一个节点**：即刻将对应行改为 `[x]`，更新状态为已勾
3. **B+ 节点特殊标记**：≥200行的节点标注 `B+.` 前缀，必须写子节点
4. **Step C 启动条件**：所有节点 checklist 必须全部 `[x]`
5. **Step C 完成时**：标记 Step C done，跑 verify_notes.py，保留结果
6. **禁止行为**：
   - 禁止在节点未全部 `[x]` 时启动 C 步骤
   - 禁止跳过 B+ 子节点细分
   - 禁止以任何理由从 outline 直接跳到 assembly
