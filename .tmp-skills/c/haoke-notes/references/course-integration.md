将所有单课笔记整合为多层次复习/学习材料。仅在全部单课笔记完成后，由用户手动触发。整合工作由主进程完成，不调用并行子 agent。

## 整合产出概览

| 层次 | 输出文件 | 作用 | 生成方式 |
|------|----------|------|---------|
| 宏观 | `知识图谱.md` | 全局坐标系，含 XMind 兼容缩进 + 法条/案例附录清单 | AI 自动 |
| 中观 | `概念追踪表.md` | 跨课次概念演进与交叉引用 | AI 自动 |
| 微观 | `整合版笔记.md` | 去重、去发散、按知识体系重新组织 | AI 自动 |
| 工具层 | `法条精读表.md` | 核心法条原文 + 要件逐项拆解，全周期参考 | AI 自动 |
| 训练层 | `辨析表.md` | 易混概念结构化对比；初版 AI 生成，用户持续追加 | AI 初版 + 用户维护 |
| 训练层 | `案例练习库.md` | 纯事实描述案例 + 考查方向；分析栏留空由用户填写 | AI 提取，用户填写 |

分工原则：AI 负责把信息组织好（输入层）；测试、盲测、主动重构、个人困惑记录由用户完成（输出层）。

## 折叠框格式规范

第四步（法条精读表）、第五步（辨析表）、第六步（案例练习库）的需要用户自测的内容必须用 `<details>` 折叠框包裹，让用户"先回忆 → 再展开对照"。Typora 在 `<details>` 内**不解析** Markdown 语法（表格变成原始竖线、列表变成纯文本），所以折叠框内必须用 HTML。

### 三条核心规则

**1. `<details>` 与 `<summary>` 同行**

```
正确：<details><summary>标题</summary>
错误：<details>
      <summary>标题</summary>
```

**2. `</summary>` 后无空行，`</details>` 前无空行**

空行会让内容脱离折叠框、暴露在外部。

**3. 折叠框内全部用 HTML 标签**

| 内容类型 | ❌ Markdown | ✅ HTML |
|---------|-------------|---------|
| 表格 | `\| 列A \| 列B \|` | `<table><tr><th>列A</th><th>列B</th></tr>...` |
| 有序列表 | `1. 第一条` | `<ol><li>第一条</li></ol>` |
| 无序列表 | `- 项目` | `<ul><li>项目</li></ul>` |
| 加粗 | `**文字**` | `<strong>文字</strong>` |
| 斜体 | `*文字*` | `<em>文字</em>` |
| 引用块 | `> 引用` | `<blockquote>引用</blockquote>` |
| 段落 | （直接写） | `<p>段落</p>` |

`<tr>` 和 `<td>`/`<th>` 之间不要换行，避免 Typora 解析异常。

### 标准折叠块示例

```markdown
**条文原文**：
> 当事人之间订立有关设立、变更、转让和消灭不动产物权的合同...

<details><summary>📋 点击展开要件拆解与论证分析</summary>
<table>
<tr><th>要件</th><th>内容</th><th>注意点</th></tr>
<tr><td>规范对象</td><td>不动产物权变动合同</td><td>动产适用不同规则</td></tr>
<tr><td>合同效力</td><td>自合同成立时生效</td><td>与物权变动时间解耦</td></tr>
</table>
<p><strong>课程论证功能</strong>：区分负担行为与处分行为的核心条文。</p>
<p><strong>出现课次</strong>：第2课（首次系统讲授）、第7课（担保物权语境）</p>
</details>
```

### 完成后的检查项

生成完成后，逐一检查：

1. 搜索 `</summary>\n\n` 和 `\n\n</details>`，有空行必须删除
2. 折叠框内是否残留 `|` 表格、`- ` 列表、`**` 加粗、`> ` 引用？改为 HTML
3. 搜索 `<details>\n<summary>`，应合并到一行
4. 折叠块数量：法条精读表 = 精读法条数；辨析表 = 概念对数；案例练习库 = 案例数

不要依赖脚本后处理把 Markdown 表格转成 HTML 折叠块——正则在中文表格、多行匹配、格式微差上不可靠。**唯一可靠的方式是撰写时直接输出正确格式**。

## 渐进披露流程

```
第零步：build_index.py → index.json（只读标题/概览/META 收纳框，不读正文）
   ↓
第一步：基于 index.json 生成知识图谱（XMind 兼容 + 法条/案例附录清单）
   ↓
第二步：locate_concepts.py → concept_map.json → 生成概念追踪表
   ↓
第三步：逐知识模块处理 → extract_module.py 提取相关章节 → 整合 → working/
        全部模块完成后：merge_outputs.py 合并为整合版笔记
   ↓
第四步：基于整合版笔记 + 知识图谱法条清单 → 法条精读表
   ↓
第五步：基于整合版笔记 + 概念追踪表 → 辨析表初版
   ↓
第六步：基于整合版笔记 + 知识图谱案例清单 → 案例练习库
```

每步只加载当前需要的内容，避免一次性载入全部笔记。1M 上下文虽然能装下，但合理控制有助于 prompt cache 命中和输出质量。

## 第零步：构建预索引

```bash
python $SKILL_DIR/scripts/build_index.py <课程目录>/output/notes --output <课程目录>/working/index.json
```

`build_index.py` 读取所有笔记的结构信息（标题层级 + 概览 + 末尾 META 折叠框中的概念/法条/案例清单），不读正文。输出 `index.json`，每篇笔记含：

- 概览（开头几百字）
- 一级 / 二级标题层级
- 概念、法条、案例、易混对清单（来自末尾 META 折叠框）
- 每个章节的起止行号（供后续模块提取使用）
- PPT 摘要字段 `ppt_summary`（一段 200 字摘要，从 data/ppt_md 自动提取）

读取：`index.json`

生成 XMind 兼容的缩进标题格式（可直接导入 XMind / 幕布），并在末尾追加法条 / 案例 / 概念清单作为附录段。输出到 `working/graph.md`，定稿后移入 `output/知识图谱.md`。

```markdown
- 定义：[简要定义]
- 关联课次：第X课、第Y课
#### 法条：[法条名]
- 核心规定：[简述]
- 关联课次：第X课
#### 案例：[案例名]
- 论证意义：[简述]
### 章节二：[子主题]
#### ...

## 模块二：[大主题名称]
### ...

***

# 附录

## 全部法条清单

| 法条 | 所属模块 | 课次 |
|------|---------|------|
| ... | ... | ... |

## 全部案例清单

| 案例 | 所属模块 | 出现课次 | 论证意义 |
|------|---------|---------|---------|
| ... | ... | ... | ... |

| 概念 | 所属模块 | 首次出现课次 | 后续涉及课次 |
|------|---------|-------------|-------------|
| ... | ... | ... | ... |
```

XMind 主体使用纯标题层级（`#` `##` `###` `####`），导入工具会自动构建大纲；附录使用 Markdown 表格便于阅读和检索。两者通过 `***` 分隔，不影响导入时的大纲提取。

## 第二步：概念追踪

```bash
python $SKILL_DIR/scripts/locate_concepts.py <课程目录>/working/index.json --output <课程目录>/working/concept_map.json
```

读取 `concept_map.json`，识别跨课次概念（在多篇笔记中出现的）。

`extract_module.py` 是按一级标题（"模块"）切片的工具，不能直接用来提取"某概念出现的所有相关段落"。概念追踪表的撰写方式：

1. 从 `concept_map['concepts'][概念名]['occurrences']` 读出该概念出现的所有 `note + section`
2. 直接打开对应的笔记文件，读取该 section 的内容（行号在 index.json 的 sections 字段）
3. 对比该概念在不同课次的讲法

输出到 `working/concept_tracking.md`，定稿后移入 `output/概念追踪表.md`：

```markdown
# [课程名称] — 跨课程概念追踪

## [概念名]

| 课次 | 讲法 | 侧重点 | 与其他课次的关联 |
|------|------|--------|-----------------|
| 第X课 | [首次引入] | [定义/基础] | — |
| 第Y课 | [再次提及] | [深化/应用] | 与第X课的区别：... |

**跨课综合**：[总结该概念的完整讲法，含老师核心观点]
```

只追踪在多个课次中出现的概念；重点展示讲法差异和递进关系，不是简单堆叠。

```markdown

```

## 第三步：模块整合

### 3a. 获取模块列表

从 `concept_map.json` 的 `modules` 字段读取知识模块（一级标题）清单。

### 3b. 逐模块处理

对每个模块：

```bash
python $SKILL_DIR/scripts/extract_module.py \
    <课程目录>/working/index.json \
    <课程目录>/working/concept_map.json \
    <课程目录>/output/notes \
    --module "模块名称" \
    --output <课程目录>/working/module_XX_模块名_raw.md
```

`extract_module.py` 按一级标题模糊匹配，从涉及该模块的所有笔记中切出对应章节，合并到 raw 文件（通常几千字）。

读取 raw 文件后：

1. 合并重复内容，保留最详细版本
2. 去除发散讨论（保留老师核心论点和反驳链）
3. 按知识体系重新组织该模块的内容
4. 输出整合后的模块笔记到 `working/module_XX_模块名.md`

changelog：

```markdown
| module-01 | 2026-04-25 | ✅ | 整合: 模块名称 | working/module_01_XX.md |
```

### 3c. 合并所有模块

```bash
python $SKILL_DIR/scripts/merge_outputs.py \
    <课程目录>/working/ \
    --output <课程目录>/output/整合版笔记.md \
    --course [课程名称]
```

changelog：

```markdown
| merge | 2026-04-25 | ✅ | 整合版笔记 (6 个模块) | output/整合版笔记.md |
```

## 第四步：法条精读表

撰写前必读：本文档「折叠框格式规范」章节。法条要件拆解必须用 `<table>` + `<details>`。

读取：`output/整合版笔记.md` + 知识图谱附录中的法条清单

操作：

1. 提取课程涉及的全部核心法条（通常 20-40 条）
2. 区分两个层级：
   - **精读层**（约 30 条）：必须掌握编号 + 内容 + 要件拆解的核心条文
   - **理解层**：理解内容即可、无需记忆编号的一般条文（不收录）
3. 对每条精读法条逐字拆解要件，标注课程论证功能

输出到 `output/法条精读表.md`：

```markdown
# [课程名称] — 法条精读表

> 仅收录需要掌握编号+内容的核心条文（精读层）。
> 使用方法：遮住"要件拆解"，自己尝试逐项还原后再对照。
```

## 第五步：辨析表初版

撰写前必读：本文档「折叠框格式规范」章节。

读取：`output/整合版笔记.md` + `output/概念追踪表.md` + 各笔记末尾 META 折叠框中的 PITFALL 列表

操作：

1. 从 PITFALL 清单 + 笔记中识别结构上易混淆的概念对（定义相近、适用场景有交叉、或在同一条文中对比出现）
2. 对每个概念对从多个维度做结构化对比
3. 为每对生成 1-2 个判断性提问，供用户自测

输出到 `output/辨析表.md`：

```markdown
# [课程名称] — 易混淆概念辨析表

> **使用说明**：
> - AI 初版：基于笔记内容生成的结构性混淆对，覆盖客观上容易混淆的概念
> - 用户追加：在精读、练习、盲测过程中将自己实际遇到的混淆点记录在"用户记录"栏
> - 自测方式：遮住"区别"列，自己先回答再对照
```

## 学习目标定向

`preferences.json` 中的 `learning_goal` 影响整合阶段策略：

### 闭卷应试

- 整合版笔记按知识体系重组，但保留高频考点的标记
- 法条精读表精读层尽量精简（聚焦真正需要默写的）
- 辨析表覆盖面广，自测题接近考试形式
- 案例练习库的考查方向写得明确具体

### 开卷应试

- 整合版笔记保留最详尽，强索引（每个概念的出现位置全部列出）
- 法条精读表收录完整条号和分款
- 辨析表的"对比详情"展开，便于考场快速翻查
- 案例库的"参考位置"必须精确到具体行 / 节

### 论文 / 研究

- 整合版笔记单独标注学说争议段，列出每位学者的具体观点
- 概念追踪表突出"讲法差异"，作为学派演变的考证依据
- 法条精读表加入立法沿革讨论
- 辨析表着重学理边界

### 自学 / 入门

- 整合版笔记按渐进难度组织，前置知识在前
- 知识图谱附 2-3 句"模块导读"，说明这个模块解决什么问题
- 法条精读表减少要件细节，强调法条解决什么问题
- 案例库的考查方向写成"启发式问题"，引导思考

如 `preferences.json` 无 `learning_goal` 字段，按"闭卷应试"作默认。

## 关键原则

### 上下文控制

- 永远不要一次性加载全部笔记
- 预索引（index.json）只含结构信息，几百行
- 概念定位图（concept_map.json）只含映射关系
- 每个模块提取的内容通常几千字
- 1M 上下文有冗余但不挥霍——cache 命中是省 token 的关键

### 渐进披露

- 第零 → 第一步：只读索引建立全局认知
- 第二步：按需读概念相关段落做交叉引用
- 第三步：按模块读相关章节做整合
- 第四 - 六步：基于整合产物生成训练层工具

### 不遗漏

- 去重是合并重复内容，不是删除知识点
- 每个知识点至少在整合版中完整呈现一次
- 辨析表 AI 初版只覆盖客观混淆对，用户追加才使其完整
- 案例练习库只提供事实和问题，不提供分析结论
